    How it works

    Authority flows down. Revocation flows down faster.

    GLEIF's August 2026 discussion paper calls for an Agent Mandate Credential and leaves sub-delegation between agents open. Writ puts the mandate's state, and the whole tree under it, in a NEAR contract.

    Who

    Rooted in a person

    Root → QVI → legal entity → employee on the official vLEI schemas, then a proposed Agent Mandate Credential to the agent. A verifier checks the chain once off-chain with keripy and signs an attestation. The issuers in this demo are mocks.

    What

    Only ever narrower

    An agent hires by spending budget links the employee already released. Payees, expiry, rate and per-payment cap can only shrink, up to 3 levels and 16 agents. Every payment is checked on-chain: payee, unpaid invoice, cap, hash-chain budget, rate, expiry.

    Gone

    The key stops existing

    NEAR lets a contract add and delete keys on its own account, and each agent key is restricted by the protocol to three methods. Revoking the root deletes every key in one batch and returns every vault: 16 agents, 17 Tgas.

    • The vLEI schemas are GLEIF's; the issuers are mocks with a fictional LEI, and no real QVI issued anything. The Agent Mandate Credential schema is a proposal, since GLEIF has not published one.
    • Testnet only, no real users yet. The company's LEI stays a commitment until a public disclosure, but funding accounts and payments are public and linkable.
    • Revocation takes effect when the signed event reaches the contract; no relayer ships with the repo. A fooled payment inside every limit, to a permitted payee, for a new invoice, still gets paid.
    • Steps 2 and 3 above are scripted so you can repeat them. The model results are real runs on a local sandbox.
